Lesson Content

DFA and NFA fundamentals

A Deterministic Finite Automaton (DFA) is a finite automaton where, for every state and every input symbol, there is exactly one next state. There is no ambiguity — the machine always knows precisely where to go next.

Formal Definition

A DFA is a 5-tuple M = (Q, Σ, δ, q₀, F) where:

  • Q = finite set of states
  • Σ = finite input alphabet
  • δ : Q × Σ → Q = transition function (exactly one next state for each state-symbol pair)
  • q₀ ∈ Q = start state
  • F ⊆ Q = set of accept states

Key Property: Determinism

"Deterministic" means the machine has no choice. Given the current state and the current input symbol, the next state is uniquely determined. There are no multiple options, no guessing, and no ε-transitions (moves without reading input).

Example: DFA accepting binary strings that contain "01"

Σ = {0, 1}. Accept any string containing "01" as a substring.

States:

  • q₀: Haven't seen a '0' yet (or last char was '1' and no "01" found)
  • q₁: Just saw a '0', waiting for '1' to complete "01"
  • q₂: Found "01" — accept! Stay here on any input.
State Input 0 Input 1
q₀ q₁ q₀
q₁ q₁ q₂
q₂ q₂ q₂

F = {q₂}. Notice every cell has exactly one entry — that's what makes it deterministic.

Real-world analogy: Vending machine

A vending machine is deterministic: insert ₱5 → go to "₱5 inserted" state. Insert another ₱5 → go to "₱10 inserted" state. At no point does the machine wonder "should I go to state A or state B?" — there's always exactly one outcome per action.

A Nondeterministic Finite Automaton (NFA) is like a DFA but with more flexibility. For a given state and input symbol, the machine can transition to zero, one, or multiple next states simultaneously. It can also make ε-transitions — moving to another state without reading any input.

Formal Definition

An NFA is a 5-tuple M = (Q, Σ, δ, q₀, F) where:

  • Q = finite set of states
  • Σ = finite input alphabet
  • δ : Q × (Σ ∪ {ε}) → P(Q) = transition function mapping to the power set of Q (a set of possible next states)
  • q₀ ∈ Q = start state
  • F ⊆ Q = set of accept states

Key Differences from DFA

DFA
δ(q, a) = exactly one state
NFA
δ(q, a) = a set of states (can be empty, one, or many)
DFA
No ε-transitions allowed
NFA
ε-transitions allowed (move without consuming input)

How acceptance works in an NFA

An NFA accepts a string if at least one possible path through the machine ends in an accept state. Think of it as the machine "guessing" the correct path. If any guess leads to acceptance, the string is accepted.

Example: NFA accepting strings ending in "01"

Σ = {0, 1}. Accept strings whose last two characters are "01".

  • q₀: Start — loop on 0 and 1 (keep reading)
  • q₁: Just "guessed" we're at the second-to-last position and saw '0'
  • q₂: Saw '1' after q₁ — accept!
State Input 0 Input 1
q₀ {q₀, q₁} {q₀}
q₁ ∅ {q₂}
q₂ ∅ ∅

F = {q₂}. Notice q₀ on input '0' goes to TWO states — that's nondeterminism!

Real-world analogy: Multiple-choice maze

Imagine a maze where at some forks, you can clone yourself and explore all paths simultaneously. If any clone reaches the exit, you win. That's how an NFA processes a string — it explores all possible paths at once.

Designing a DFA requires thinking about what information you need to "remember" about the input processed so far. Each state represents a distinct memory condition.

Step-by-step DFA design process

  1. Identify the language — What strings should be accepted?
  2. Determine what to remember — What condition distinguishes accepted strings?
  3. Create states — One state per distinct "memory condition"
  4. Define ALL transitions — Every state must have exactly one transition for EACH input symbol
  5. Mark start and accept states
  6. Test thoroughly — Try accepted and rejected strings

Example: DFA for strings with an even number of 'a's

Σ = {a, b}. Accept strings where the count of 'a' is even (0, 2, 4, ...).

What to remember: Is the count of 'a's seen so far even or odd?

  • q₀ (even count — start here, also accept state since 0 is even)
  • q₁ (odd count)
State Input a Input b
q₀ (accept) q₁ q₀
q₁ q₀ q₁

Test: "aab" → q₀→q₁→q₀→q₀ → ACCEPT ✓ (2 a's = even)

"ab" → q₀→q₁→q₁ → REJECT ✗ (1 a = odd)

Common mistake

Forgetting to define transitions for EVERY state-symbol pair. In a DFA, if you leave a transition undefined, the machine is incomplete. Every state must handle every possible input symbol.

NFAs are often easier to design than DFAs because you can "guess" the right path. You don't need to handle every transition — undefined transitions simply mean "this path dies."

NFA design strategies

  1. Pattern matching: Guess when the pattern starts, then verify it character by character
  2. ε-transitions for "free" moves: Use ε-transitions to jump between phases of recognition without consuming input
  3. Multiple initial paths: Let the start state branch into multiple possibilities

Example: NFA for strings containing "aba" OR "bab"

Σ = {a, b}. Accept if the string contains "aba" or "bab" as a substring.

Strategy: Use ε-transitions from start to two separate "pattern detector" branches.

  • q₀: Start — ε-transition to both branches, also loops on a,b
  • Branch 1 (detect "aba"): q₁→q₂→q₃→q₄(accept)
  • Branch 2 (detect "bab"): q₅→q₆→q₇→q₈(accept)

This would be much more complex as a DFA (many states needed to track both patterns). NFA makes it simple by exploring both possibilities in parallel.

Example: NFA with ε-transitions

Accept strings that are either all a's (length ≥ 1) OR all b's (length ≥ 1).

  • q₀: Start — ε→q₁ and ε→q₃
  • q₁: Read 'a' → q₂ (accept), loop on 'a'
  • q₃: Read 'b' → q₄ (accept), loop on 'b'

The ε-transitions let the NFA "choose" which branch to follow without reading input.

When to use NFA vs DFA

Use NFA for design convenience — they're simpler to create for pattern-matching problems. Use DFA for implementation — computers execute DFAs directly since there's only one path to follow.

One of the most important theorems in automata theory: DFAs and NFAs are equivalent in power. Every language that can be recognized by an NFA can also be recognized by a DFA, and vice versa.

What "equivalent" means

  • For every NFA, there exists a DFA that accepts exactly the same language
  • For every DFA, it is already an NFA (a DFA is a special case of NFA)
  • Both recognize exactly the class of regular languages

Why this matters

NFAs are easier to design (less states, more intuitive for pattern matching). DFAs are easier to implement (one path, fast execution). Since they're equivalent, you can design with NFA convenience and convert to DFA for execution.

The trade-off

The equivalent DFA may have exponentially more states than the original NFA. An NFA with n states can require up to 2ⁿ states in the equivalent DFA (though in practice it's often much less).

Example: An NFA with 3 states might convert to a DFA with up to 8 states (2³ = 8), though many of those states may be unreachable and can be removed.

Key takeaway

Nondeterminism does NOT add computational power to finite automata. It adds convenience — simpler designs with fewer states — but the resulting machine recognizes the same class of languages.

The subset construction (also called powerset construction) is a systematic algorithm to convert any NFA into an equivalent DFA. The idea: each DFA state represents a set of NFA states the machine could be in simultaneously.

Algorithm Steps

  1. Start state of DFA = ε-closure of NFA's start state (the set of all states reachable from q₀ via ε-transitions)
  2. For each DFA state (set S) and each input symbol a: Compute the set of NFA states reachable from any state in S on input a, then take the ε-closure. This becomes the next DFA state.
  3. Repeat until no new DFA states are generated.
  4. Accept states of DFA = any DFA state (set) that contains at least one NFA accept state.

Complete Example

Convert this NFA (accepting strings ending in "01") to a DFA:

NFA: Q = {q₀, q₁, q₂}, Σ = {0,1}, start = q₀, F = {q₂}

NFA State 0 1
q₀ {q₀, q₁} {q₀}
q₁ ∅ {q₂}
q₂ ∅ ∅

Subset Construction:

DFA start: {q₀} (no ε-transitions here)

{q₀} on 0 → {q₀, q₁} | on 1 → {q₀}

{q₀, q₁} on 0 → {q₀, q₁} | on 1 → {q₀, q₂}

{q₀, q₂} on 0 → {q₀, q₁} | on 1 → {q₀}

DFA State 0 1 Accept?
A = {q₀} B A No
B = {q₀,q₁} B C No
C = {q₀,q₂} B A Yes (contains q₂)

The resulting DFA has 3 states and accepts exactly the same language as the original NFA!

ε-closure reminder

The ε-closure of a state q is the set of all states reachable from q by following zero or more ε-transitions. Always compute ε-closure after each transition step.

Learning Activities

Group Activity

"NFA vs DFA Design Challenge"

  1. Form groups of 4–5 members.
  2. Each group receives a language specification (e.g., "strings containing '110'", "strings with at most two b's").
  3. Design both an NFA and a DFA for the same language.
  4. Compare: Which has fewer states? Which was easier to design?
  5. Convert your NFA to a DFA using subset construction. Does it match your direct DFA?
  6. Present findings to the class (7 minutes).
Discussion points: Why might the NFA have fewer states? When would you prefer DFA over NFA in practice?
