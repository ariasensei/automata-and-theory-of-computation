Lesson Overview

Let’s begin with a simple question: how do machines make decisions?

In this lesson, you will be introduced to one of the most important ideas in computer science: computation. At first, the word may sound technical, but the idea is actually very familiar. Every time a phone unlocks after reading your fingerprint, a traffic light changes color, or a search bar checks what you typed, a system is receiving information, following rules, and producing a result. Theory of Computation helps us understand these systems in a clearer and more organized way.

Big Idea

Even complicated digital systems can often be understood as a series of simple states, inputs, and responses.

By the end of this lesson, you should be able to:

  • explain computation using simple everyday examples;

  • describe automata as simplified models of machines;

  • identify the meaning of state, transition, and acceptance;

  • connect these ideas to systems you already use every day.

Core Lesson

The first steps into computation

1. What is computation?

Computation is the process of taking in information, following a set of rules, and producing an output. You can think of it as a decision-making process. For example, when you type your PIN into an ATM, the machine receives your input, checks whether it matches the stored record, and then decides whether to allow access or reject the attempt. The same basic pattern appears in many technologies around us: input, rules, and output.

Real-world scenario

Imagine a pedestrian traffic light near a school crossing. When someone presses the button, the system does not randomly choose what to do. It follows a rule: wait for the correct time, then switch from STOP to WALK. That simple rule-following behavior is already a form of computation.

2. Automata: simple models of how systems behave

An automaton is a simplified model of a machine or system. Instead of focusing on wires, screens, and physical parts, we focus on behavior. We ask: What condition is the system currently in? What input does it receive? What happens next? This makes complicated systems much easier to study. In computer science, simplifying a problem this way helps us understand how a machine behaves without getting lost in unnecessary details.

State

The current condition of the system. For example: LOCKED, UNLOCKED, WAITING, or PROCESSING.

Transition

The movement from one state to another after an input or event happens.

Acceptance

The point where the machine decides that the input is valid, correct, or recognized.

Pause and think

Think about the screen lock on your phone. What are its possible states? What input causes it to change? In many cases, you are already describing an automaton without realizing it.

3. Formal languages and recognizing patterns

In Theory of Computation, a language is not just something spoken like English or Filipino. A language is a set of valid strings that follow a pattern or rule. For example, a valid email address, a student ID number, or a password format all follow certain rules. Automata help us check whether an input belongs to the language or not. If the input follows the rule, it is accepted; if not, it is rejected.

Alphabet

The symbols we are allowed to use, such as letters, digits, or punctuation marks.

String

A sequence of symbols, such as 1011, AB123, or hello.

Language

A set of strings that satisfy a certain rule or pattern.

Why it matters

You already use these ideas every day

Compilers

When you write C code in GCC or Python in PyCharm, the compiler reads your code and checks: Does every opening bracket have a closing one? Is each variable declared before use? If a rule is broken, it rejects the code with an error message—automaton behavior: input (code) → rules check → output (accept or reject).

Language Tools

When you type in Google Docs, Grammarly watches every sentence. It recognizes patterns: does this look like a run-on? Does the verb agree with the subject? These tools use automata-like rules to scan patterns and suggest corrections instantly.

Cybersecurity

Bank firewalls use regex automata to block SQL injection attacks like' OR '1'='1. The system recognizes forbidden patterns and rejects the input before it reaches the database. Your bank's login page runs this check millions of times per day.

Everyday Devices

An elevator in a mall receives button presses (input) and changes states: IDLE → MOVING-UP → STOPPED-AT-FLOOR-3 → MOVING-DOWN. A vending machine accepts coins, checks if you have enough money (state), then dispenses a snack. Both are automata in the real world.

Collaborative learning

Group Activity: Model a Familiar System

Work with your group and choose one system you know well, such as an ATM, a rice cooker, a vending machine, or a school gate scanner. Talk about what the system can do, what inputs it receives, and how it changes from one condition to another.

Your output

Create a simple state diagram or flow chart, then explain your system in your own words.

Personal reflection

Individual Activity: Spot the Automaton

Think of one digital or mechanical system you used today. It could be a phone lock screen, elevator, online form, or even a microwave oven. Try to describe it as a system that receives an input and makes a decision.

Guide question

What are its possible states? What event causes it to move from one state to another?

Remember this

Key takeaways before you move on

If you remember these four ideas, you already have a strong starting point for the next lessons.

Computation means receiving input, following rules, and producing an output.

An automaton is a simplified model used to study how a system behaves.

States and transitions help us describe how a system changes over time.

Formal languages are sets of valid strings that follow a rule or pattern.
