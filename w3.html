Lesson Content

Finite automata fundamentals

A Finite Automaton (FA) is the simplest model of computation. It is an abstract machine that has a fixed, finite number of states and moves between those states based on input symbols. Think of it as a machine that reads a string of characters one at a time, from left to right, and at the end decides whether to accept or reject the string.

Formal Definition

A finite automaton is a 5-tuple M = (Q, Σ, δ, q₀, F) where:

  • Q = a finite set of states
  • Σ (sigma) = a finite set of input symbols (alphabet)
  • δ (delta) = transition function (Q × Σ → Q)
  • q₀ = the start state (q₀ ∈ Q)
  • F = set of accept/final states (F ⊆ Q)

Real-world analogy: Turnstile gate

A subway turnstile has two states: Locked and Unlocked. Insert a coin → it moves to Unlocked. Push the bar → it moves to Locked. This is a finite automaton with 2 states and 2 input symbols.

Every finite automaton is made up of exactly five components. Let's explore each one with a concrete example.

Example: FA that accepts strings ending in "1" over alphabet {0, 1}

Q = {q₀, q₁}
Two states: q₀ (not ending in 1) and q₁ (ending in 1)
Σ = {0, 1}
The input alphabet — only 0s and 1s allowed
q₀ = q₀
We start in state q₀
F = {q₁}
q₁ is the only accept state

Transition Function δ

State Input 0 Input 1
q₀ q₀ q₁
q₁ q₀ q₁

Think of it this way

The transition function is like a rulebook: "If you're in state X and you read symbol Y, go to state Z." It tells the machine exactly what to do at every step.

A state represents a condition or situation the machine can be in at a given time. A transition is the movement from one state to another triggered by reading an input symbol.

Start → q₀

Read '0' → move to q₀

End of string. Current state = q₁ ∈ F → ACCEPTED ✓

Example: Tracing "100"

Start → q₀ → read '1' → q₁ → read '0' → q₀ → read '0' → q₀

End of string. Current state = q₀ ∉ F → REJECTED ✗

A transition diagram (also called a state diagram) is a visual representation of a finite automaton using circles and arrows.

Circles = States
Each circle is labeled with the state name
Double circle = Accept state
Final/accepting states have a double border
Arrows = Transitions
Labeled with the input symbol that triggers them
Unlabeled arrow = Start
An arrow from nowhere points to the start state

Diagram for "strings ending in 1"

→ q₀ —1→ q₁

q₀ loops on '0', q₁ loops on '1', q₁→q₀ on '0', q₀→q₁ on '1'

Drawing tips

1) Draw all states as circles first. 2) Mark the start state with an incoming arrow. 3) Double-circle the accept states. 4) Add labeled arrows for every transition in your table.

A finite automaton accepts a string if, after reading all input symbols, the machine ends in an accept state. The language of an FA is the set of all strings it accepts.

Example

For our FA accepting strings ending in '1':

  • L(M) = {1, 01, 11, 001, 011, 101, 111, ...}
  • String "01" → ends in q₁ → Accepted
  • String "00" → ends in q₀ → Rejected
  • String "ε" (empty) → stays in q₀ → Rejected

Key distinction

Accept = ends in a final state after all input is consumed. Reject = ends in a non-final state. The machine always reads the entire string — it never stops early.

Designing an FA means figuring out what states you need to "remember" about the input so far. Follow this step-by-step process:

  1. Understand the language — what strings should be accepted?
  2. Determine what to remember — what condition must hold at the end?
  3. Create states — each state represents one "memory condition"
  4. Define transitions — for each state and each input symbol, where do you go?
  5. Mark start and accept states
  6. Test with example strings

Design exercise: FA for strings containing "01" as a substring

Alphabet Σ = {0, 1}. Accept any string that has "01" somewhere in it.

States needed:

  • q₀: Haven't seen anything useful yet
  • q₁: Just saw a '0' (might be the start of "01")
  • q₂: Have seen "01" — accept! (stay here forever)

Pro tip

Always test your design with strings that should be accepted AND strings that should be rejected. If any test fails, revise your transitions.

Practice and Apply

Learning activities

Group Activity

"Design and Present Your Own FA"

  1. Form groups of 4–5 members.
  2. Each group is given a language specification (e.g., "strings starting with 0", "strings with even number of 1s").
  3. Design the FA: list Q, Σ, δ, q₀, F.
  4. Draw the transition diagram on paper or whiteboard.
  5. Trace at least 3 strings (2 accepted, 1 rejected) to verify.
  6. Present to the class (5 minutes).
Discussion points: Why did you choose those states? What does each state "remember"?

Individual Activity

"Trace and Decide"

  1. Given the FA M = ({q₀, q₁, q₂}, {a, b}, δ, q₀, {q₂}) with transitions: δ(q₀,a)=q₁, δ(q₀,b)=q₀, δ(q₁,a)=q₂, δ(q₁,b)=q₀, δ(q₂,a)=q₂, δ(q₂,b)=q₂
  2. Trace these strings: "aa", "aba", "baa", "bb", "aab"
  3. For each string, show the full state sequence and write ACCEPT or REJECT.
  4. Describe in one sentence what language this FA accepts.
Rubric: Correct traces (60%), correct accept/reject (20%), language description (20%)
